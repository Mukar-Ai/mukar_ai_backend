DICTIONNAIRE DES DONNÉES — MODULE 1
Extraction des informations financières et documentaires d’une PME

OBJECTIF
Ce document accompagne le JSON d’extraction produit par le LLM.
Il décrit la signification de chaque champ afin que le LLM sache précisément
quelles informations rechercher dans les documents du client et comment les
restituer.

PRINCIPES GÉNÉRAUX

1. Extraction uniquement
Extraire uniquement les informations réellement présentes dans les documents
fournis.

2. Interdiction d’invention
Ne jamais inventer, estimer ou supposer une valeur absente des documents.

3. Valeur absente
Utiliser null lorsqu’une valeur n’est pas trouvée.

4. Statuts
EXTRACTED : information trouvée et exploitable.
MISSING : information attendue mais absente.
CONFLICT : plusieurs valeurs contradictoires ont été trouvées.
LOW_CONFIDENCE : information trouvée mais extraction/interprétation incertaine.
NOT_APPLICABLE : information ne s’applique pas au dossier.

5. Source obligatoire
Toute information extraite doit conserver sa source : nom du document,
type de document, page, section, libellé et extrait textuel lorsque disponible.

6. Pas de calcul
Le LLM d’extraction ne doit pas calculer les ratios financiers ni interpréter
la situation financière. Il extrait les données nécessaires aux calculs
ultérieurs du Module 2.

7. Données pluriannuelles
Toute donnée financière pouvant exister pour plusieurs exercices doit être
organisée par période/exercice.

8. Données répétitives
Toute information pouvant apparaître plusieurs fois doit être représentée
sous forme de liste d’objets : transactions, dettes, comptes bancaires,
bons de commande, proformas, contrats, marchés, flux futurs, etc.

────────────────────────────────────────
1. APPLICATION
────────────────────────────────────────

application
Informations générales concernant la demande de crédit.

application_id
Identifiant unique de la demande de crédit. Peut provenir du dossier,
du formulaire de demande ou d’un document interne.

application_date
Date de dépôt ou de formulation de la demande de crédit. Ne pas confondre
avec la date de création de l’entreprise.

analysis_reference_period
Période principale couverte par les informations utilisées pour l’analyse.

start_date
Date de début de la période analysée.

end_date
Date de fin de la période analysée.

status
État global de l’extraction de la demande :
EXTRACTED, INCOMPLETE ou READY_FOR_ANALYSIS.

source
Source générale de l’information de demande lorsqu’elle apparaît dans
un document.

confidence
Niveau de confiance global associé à cette information.

────────────────────────────────────────
2. SOURCE
────────────────────────────────────────

source
Objet permettant de retrouver exactement l’origine d’une donnée.

document_name
Nom du fichier/document dans lequel l’information a été trouvée.

document_type
Type du document source.
Exemples :
FINANCIAL_STATEMENT
BALANCE_SHEET
BANK_STATEMENT
TAX_DOCUMENT
RCCM
STATUTES
PURCHASE_ORDER
PROFORMA
CONTRACT
BUSINESS_PLAN
LOAN_AGREEMENT
OTHER

page
Numéro de la page où l’information a été trouvée.

section
Section du document contenant l’information.
Exemples :
Compte de résultat
Bilan actif
Bilan passif
Transactions
Dettes financières
Informations fiscales

label
Libellé associé à la donnée dans le document.
Exemple : « Chiffre d’affaires », « EBE », « Dettes fournisseurs ».

text_excerpt
Court extrait du texte ou de la ligne/tableau permettant de vérifier
l’information extraite.

4. CREDIT_REQUEST
────────────────────────────────────────

credit_request
Informations relatives au financement demandé.

requested_amount

purpose
Objet principal du financement.
Exemples :

────────────────────────────────────────
5. FINANCIAL_STATEMENTS
────────────────────────────────────────

financial_statements
Données issues des états financiers, structurées par exercice.

periods[]
Liste des exercices comptables disponibles.

period
Exercice concerné par l’objet.

revenue_ht
Chiffre d’affaires hors taxes de l’exercice.

revenue_ttc
Chiffre d’affaires toutes taxes comprises lorsqu’il est explicitement indiqué.

purchases
Montant des achats de l’exercice lorsqu’il est disponible.

cost_of_goods_sold
Coût des marchandises vendues ou coût directement associé aux ventes
lorsqu’il est explicitement identifiable.

gross_margin
Marge brute telle qu’elle apparaît dans les états financiers.
Ne pas calculer cette marge dans le Module 1.

operating_expenses
Charges d’exploitation identifiables pour l’exercice.

ebe
Excédent Brut d’Exploitation de l’exercice.

depreciation
Dotations aux amortissements/amortissements lorsque l’information
est disponible.

financial_expenses
Charges financières, intérêts et frais financiers identifiables.

taxes
Impôts et taxes supportés par l’entreprise lorsqu’ils sont identifiables.

net_income
Résultat net de l’exercice.

Pour chaque donnée financière, conserver :
value
currency
source
confidence
status

────────────────────────────────────────
15. RÈGLE DE PROVENANCE POUR CHAQUE DONNÉE
────────────────────────────────────────

Lorsqu’une donnée est extraite, elle doit conserver au minimum :

value
Valeur effectivement trouvée dans le document.

source
Origine exacte de la valeur.

confidence
Niveau de confiance compris entre 0 et 1.

status
État de la donnée.

Exemple :

ebe:
  value: 18500000
  currency: XAF
  source:
    document_name: Etats_financiers_2025.pdf
    document_type: FINANCIAL_STATEMENT
    page: 13
    section: Compte de résultat
    label: Excédent Brut d’Exploitation
    text_excerpt: "EBE : 18 500 000 FCFA"
  confidence: 0.98
  status: EXTRACTED

────────────────────────────────────────
16. INTERDICTIONS ABSOLUES
────────────────────────────────────────

Le LLM d’extraction ne doit jamais :

- inventer une donnée absente ;
- remplacer une valeur absente par une estimation ;
- choisir silencieusement entre deux valeurs contradictoires ;
- inventer une source ;
- inventer un numéro de page ;
- calculer un ratio financier ;
- interpréter la rentabilité ;
- interpréter la capacité de remboursement ;
- produire un score de risque ;
- produire une recommandation de crédit.

Son rôle dans le Module 1 est uniquement :

DOCUMENTS
→ EXTRACTION
→ NORMALISATION
→ PROVENANCE
→ IDENTIFICATION DES MANQUANTS
→ IDENTIFICATION DES CONFLITS
→ JSON STRUCTURÉ
